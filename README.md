完整解压程序包，双击 `翻译姬·语音版.exe`；保留 `_internal`、`runtime` 和其他随包文件，不能只复制 EXE。
程序不包含模型、账号、个人配置或本机管理员授权。首次使用在“模型管理”下载所需模型；离线翻译须选择“本地翻译”。

本版修复翻译模型下载链路：已核验的官方国内源优先、备用源、断点续传、有界重试、完整性校验及具体错误提示。

当前源码运行及打包入口为 `projects/fanyiji-voice`，使用 Python 3.12 和该项目自己的虚拟环境。语音版不再提供 Chrome 原生字幕模式。
Chrome 字幕版已在本地独立拆分，后续另行发布；两版独立保存设置、日志、队列和浏览器资料，模型权重保持外置。

## 拆分前版本说明（v0.1.0）

下方及根目录原源码保留供旧版本追溯；开发语音版 0.1.1 请使用上方独立项目，勿使用根目录旧入口。

翻译姬（内部标识 `FanyiJi`，Python 包与命令行入口 `fanyiji`）是 Windows 实时语音翻译字幕工具。采集麦克风和电脑播放声音，分别生成中日互译字幕。支持本地模型离线翻译、Codex CLI 订阅翻译、本地暂译与云端 CLI 终稿并行、国内 CLI 账号翻译，以及内置 Google / 有道网页翻译。程序包不包含模型权重；本地模式下载完成后可以断网使用，无需登录、API Key 或安装 Python。

### 程序包首次使用

1. 将 `FanyiJi-v0.1.0-windows-x64.zip` **完整解压**到一个文件夹，然后双击其中的 `翻译姬.exe`，无需安装 Python。保留随包提供的 `_internal`、`runtime` 及其他文件，不能只抽取一个 EXE。
2. 设置麦克风、电脑声音开关及翻译方向，在“模型管理”下载所需模型。程序包不内置模型；首次下载需要联网，下载完成后可使用本地翻译模式离线运行。模型位置与旧版本复用规则见“本地数据”，更新程序不需要重新下载未变化的模型。
3. Codex CLI 是可选的联网翻译源，需要自行安装 CLI、使用自己的 ChatGPT 订阅账号登录，并消耗该账号的可用额度。程序包不提供账号、订阅或登录资料；使用本地翻译不需要 Codex。
4. 使用“直播浏览器”、指定浏览器音源采集或 Google / 有道网页翻译时，需要 Microsoft WebView2 Evergreen Runtime。缺少时可通过程序中的“微软官方内核下载”安装；默认麦克风或电脑声音配合本地 / Codex 翻译不需要打开内置浏览器。

**公开分发的程序包不提供本机管理员弹幕推送权限**，也不携带管理员启用标记、浏览器登录状态、过滤规则或个人数据。

## 产品方案

- 启动即用：首次选择两路音频开关和翻译方向，后续沿用配置；关闭的通道隐藏。
- 准确优先：本地讲话筛选、多语识别、自然停顿分句和长句拆分，再按通道翻译。
- 翻译源可选：离线本地、Codex CLI、国内 CLI、混合模式、Google 网页、有道网页；新增选项不改变已保存的选择，语音识别仍在本机完成。
- 模型独立管理：下载、导入、自行命名、完整性校验和切换；程序包不携带模型权重。
- 专用模型：独立积累和审核数据，训练前检查；未完成验收前保持使用入口关闭。
- 展示范围：识别支持中文、日语、英语；翻译目标为中文或日语，界面提供三种语言。

新安装采用 `%LOCALAPPDATA%/FanyiJi`。旧版本已存在设置、模型或专用数据时，程序原地复用旧数据目录；新目录存在时优先使用新目录，不搬移或复制模型。新 `FANYIJI_DATA/MODELS/RUNTIME` 环境变量优先，保留 `LOCAL_SUBTITLES_DATA/MODELS/RUNTIME` 兼容别名。

## 使用流程

1. 使用已构建程序时，双击“翻译姬”快捷方式或完整解压后启动程序文件夹中的 `翻译姬.exe`。从 GitHub 下载源码时，先按下方“开发与打包”安装依赖，再执行 `python run.py`；源码仓库不包含快捷方式、程序包、模型或浏览器登录资料，程序包通过上方 Releases 入口单独下载。
2. 首次启动分别设置麦克风、电脑声音的开关和翻译方向。“只翻译讲话（过滤音乐/唱歌片段）”默认开启，可在“更改设置”中关闭，并保存到上次设置。关闭的通道隐藏，只开一路时占满字幕区，两路关闭时待机。
3. 本地模型缺失时，显示“模型管理”。识别仅使用 SenseVoice INT8，分句使用 Silero VAD；下载并校验后点击“使用选中模型”。Codex / Google / 有道不需要本地翻译权重，已有本地翻译模型仍可下载、导入和切换。
4. 后续启动沿用音频设置和模型选择，直接开始。通过“更改设置”和“模型管理”修改；模型切换期间暂停字幕，释放当前推理实例，再加载所选模型。

主窗口默认高度使用允许的最小值 530，宽度按 21:9 计算并取整为 1237（Qt 逻辑像素），仍可手动调整。主窗口显示实际加载的识别模型、翻译模型、CPU/CUDA 与讲话筛选状态。模型管理分别标记“本次选择”和“当前已加载”；选择后必须成功加载，才显示为当前使用。暂停保留已加载模型，加载失败会显示失败状态。

## 两套独立字幕模式

主窗口提供“标准语音翻译”和“Chrome 实时字幕翻译”切换按钮。切换会停止上一套流程、清除显示中的旧字幕，并保留标准模式的音频、识别、翻译和模型设置。默认仍为标准模式。

Chrome 模式由 Chrome 提供识别与中文翻译，不运行 SenseVoice、VAD 或 CLI 翻译；前置音频处理默认关闭。主窗口点击“Chrome 直播间”，填写房号后，推荐手动点击“打开专用 Chrome 直播间”。程序使用已安装的官方 Chrome 和独立资料目录 `chrome-caption/dedicated-profile`；首次登录由你在专用窗口自行完成，后续沿用这份登录状态，不复制个人 Chrome 或原内置浏览器的登录资料。程序管理一个专用窗口；重复打开同一房间复用当前窗口，更换房间先关闭旧的专用窗口。

“Chrome 前置音频处理（实验）”提供关闭与 GTCRN 语音增强两种选择，仅适用于程序管理的专用 Chrome。选项独立保存在 `chrome-caption-settings.json` 的 `audio_processing` 字段，不改变标准语音模式设置；只读连接现有 Chrome 时保留选择、实际关闭处理。保存或点击“应用 Chrome 音频处理”不会自动打开浏览器，也不会开启弹幕同步。处理模型单独下载，不随程序打包。GTCRN 主要减少噪声和部分背景声，不能锁定主播、分离游戏角色讲话或保证去除唱歌；Chrome 是否正确识别处理后的音频需要实机验证，以运行状态为准。

短暂断流会先恢复原音，再按 1、2、4、8 秒重建音频通道，最长间隔 8 秒；恢复不刷新直播页、不打开新窗口，也不重播旧音频。模型缺失、无效或音源身份变化会停止并提示。点击同一模型的“应用”可重启已经结束的处理线程，正常运行时不重复创建。日志保留首次实际故障及恢复次数，界面区分增强运行、自动恢复和原音回退。

字幕读取每 2 秒报告独立心跳。读取进程失联超过 15 秒才自动恢复（首次启动宽限 30 秒），按 1、2、4 秒最多重试 3 次；字幕暂时没有新字只显示文字更新年龄，不触发重启。恢复仅重启读取进程，保留浏览器与现有字幕，不重复发送历史内容。健康时间和音频处理耗时均不是从声音到字幕显示的总延迟。

“连接现有 Chrome 直播间”保留为可选的只读方式：先自行打开目标房间并切到该标签页，再点击连接。此方式沿用现有登录和字幕设置，不启动、导航或关闭你的 Chrome，也不隐藏其字幕或使用它发送弹幕。“复制直播间地址”仅复制到本机剪贴板；“Chrome 字幕设置说明”只在翻译姬内显示操作指引，不自动进入浏览器设置。旧版仅保存房间号的配置继续按只读连接处理，不会因更新自动打开专用 Chrome。

首次使用需要启用 Chrome 实时字幕、添加日语，再开启实时翻译并选择中文；专用资料的字幕偏好会预设相应选项，浏览器仍可能需要首次下载或用户确认。“隐藏原生字幕（取消勾选后显示）”仅操作程序持有的专用 Chrome 气泡，尝试以透明方式隐藏并继续读取；其兼容性属于实验功能，不能保证所有 Chrome 版本和窗口布局都可用。只读连接的原生气泡需保持可见。读取中断时可点击“恢复原生字幕”，该操作同时取消并保存隐藏选项，停止自动隐藏，再恢复气泡显示并刷新专用直播页，不自动进入 Chrome 设置。隐藏与恢复互斥；再次隐藏需手动勾选。程序关闭专用窗口前尝试恢复原来的透明度。

房间、模式、隐藏选项和推送设置独立保存在本地数据目录的 `chrome-caption-settings.json`；此文件不保存登录凭证，专用登录资料留在外置 Chrome 资料目录，不进入程序包。保存设置及重启翻译姬均不会自动打开直播间；需要手动打开专用窗口或连接已有窗口。切换回标准模式会恢复原来的音源和翻译设置。

**目前为实验功能**。程序通过 Windows UI Automation 检查目标 Chrome 页面并读取原生字幕气泡的 `CaptionBubbleLabel`，兼容不提供 `TextPattern` 的窗口；不从网页正文补取字幕。只读方式允许保留其他标签页，但目标房间需为当前标签页，并有唯一可识别的目标窗口和气泡。专用 Chrome 只保留一个目标直播标签页；房间不符或出现多个页面时停止推送提交。房间地址只能确认页面，不能证明 Chrome 当前字幕一定来自该房间：Chrome 自行选择媒体音源，其他前台或后台媒体可能替换字幕来源；本功能不锁定主播，也不能分离游戏角色讲话。房间未开播时，轮播中的讲话仍可产生字幕供采集；没有讲话、Chrome 尚未出现气泡时，等待字幕属于正常状态。

每行显示为“Chrome 实时译文”，只提供译文，没有可读取的日语原文；需要中日对照时使用标准模式。句子按中文句末、ASCII `?!` 或原文本换行拆分，长段落按长度拆分；视觉折行不作为语义断句，半句续写和局部修订更新原字幕行，保留能够对齐的其他已知句子。Chrome 没有官方句子终稿信号，程序根据句末及 1.2 秒稳定时间判断推送候选，不把界面标签当作官方终稿。拉丁专名和 Chrome 临时的 `�` 可以保留供显示，不会放宽发送正文的严格中文规则。Chrome 译文不用于专用模型训练或原来的声音至终稿延迟统计。

专用 Chrome 的弹幕同步只在已获本机授权的管理界面显示，分发版不开放。手动打开专用直播间或明确开启同步后，当前画面中的完整中文句和后续新句稳定 1.2 秒、通过中文校验后即可进入持久待发队列，不等待发送间隔或登录检查才保存；不完整尾句继续等待句末。自动恢复或重连不会重新扫描历史字幕发送。未稳定候选可以修订；已入队但尚未提交 POST 的内容也可更新，修订期间等待重新稳定，不重复加入同一条。POST 开始后冻结该内容；结果未知或已清空的消息不会因字幕修订重新入队。含外文或无效字幕只供显示，不进入弹幕队列。

状态分别显示已写盘待发、单字待合并、尚未确认候选及中文校验拦截；“译文已稳定，等待发送”表示内容已保存。正文至少 2 个有效字符的每句译文独立进入 FIFO 队列；汉字、数字各计 1 个字符，空格和外层 `【】` 不计入此阈值。“母亲”“逃跑”等 2 字短句直接独立发送。正文不足 2 个字符时保留在原队列位置，显示“等待下一句合并”，仅与紧接的下一句合并，不跳过。

每条弹幕连同 `【】` 的加权长度最多 40：汉字计 2，ASCII 数字及空格计 1，`【`、`】` 各计 2；账号实际允许值更小时使用较小上限。长句到上限直接切分，余文成为下一段，不从前段搬字均衡尾段；满 2 个字符的尾段独立发送，最后不足 2 个字符的尾段才保留并按单字片段规则处理。历史合并记录仍兼容读取。发送目标必须与专用 Chrome 打开的房间相同，当前不支持跨房间发送。推送复用现有队列、去标点、10 秒判重、本地过滤规则及结果核验，发送间隔至少 3.5 秒；“清空待发队列”提供手动清理入口。接口回执仅表示收到响应，页面可见仅表示发送页面观察到内容，均不等于独立确认所有观众收到广播。请求超时或投递结果未知时停止盲目重发，继续只读核验；只有匹配消息的新增出现次数确认后才恢复后续发送。只读连接现有 Chrome 不进入弹幕推送。

当前已完成代码和模拟测试；透明隐藏后的持续字幕读取、真实弹幕回执与广播、连续直播音频的速度和准确率仍未完成实机验收。Chrome 版本或辅助功能布局变化可能导致无法读取，届时可切回标准模式。

Google 说明实时字幕的识别在本机进行，启用实时翻译时字幕文字发送到 Google；翻译需要联网，语言支持及可用条件以 [Chrome 官方帮助](https://support.google.com/chrome/answer/10538231?hl=zh-Hans) 为准。原生字幕可访问结构参考 [Chromium CaptionBubble](https://github.com/chromium/chromium/blob/main/components/live_caption/views/caption_bubble.cc)，并非稳定对外 API。

## 界面语言与本地模型导入

首次设置和“更改设置”提供简体中文、日本語、English。首次保存后进入主界面即生效；更改已有设置后重启生效。已有配置默认沿用简体中文；改变界面语言不改变采集通道、翻译方向、当前模型或字幕正文。

“模型管理”顶部提供唯一的“导入本地模型”入口：选择文件夹、ZIP 或模型文件，检测兼容模型，再填写自定义名称并导入。导入后模型作为独立条目保存，名称与内部 ID、存储路径分离。导入期间可查看进度或取消，全程无需联网；完成后仍需点击“使用选中模型”，不会自动更换当前模型。

预设版本按可信清单核对必要文件、大小和 SHA-256；兼容的自定义 GGUF 另校验格式、元数据、权重结构并记录本地完整性，不把自算校验值称为官方校验。识别模型只接受兼容的 SenseVoice 权重与词表；其它 ASR 模型不再提供下载、切换或导入入口。原始导入包保留，翻译模型导入方式不变，文件和注册信息存储在程序之外，不进入打包文件。

## 专用本地模型（积累数据，暂未开放使用）

主窗口的“专用模型”打开独立管理窗口。数据积累默认开启，沿用实际字幕流水线的音频、识别原文和译文，不重复采集或运行第二套语音识别。积累开关单独保存，关闭后下次启动仍保持关闭，不改变采集通道和当前翻译模型。

- 独立目录为 `%LOCALAPPDATA%/FanyiJi/specialized_model`，音频在 `audio`，原文、各版本及带模型来源的候选在 `corpus.sqlite3`；训练集、方案和 adapter 分别存放，不进入安装包。
- 点击“对照本地模型”后暂停字幕并释放当前模型，依次用已经下载的 Hy-MT2 1.8B、Hy-MT2 7B、Qwen3 1.7B 翻译同一批完整原文，每批最多30句。只写入候选，结束后恢复原字幕状态和模型设置；不追加 Codex 请求。30B 不自动参与，以免占满本机32GB内存。
- 可逐段播放录音、查看本地模型与 Codex 候选。确认原话完整准确、所选本地译文正确及素材允许训练后，才可核准本地候选。暂译、识别存疑、失败、旧版本和未核对结果不作为训练答案。
- Codex 候选保留来源用于隔离对照，当前不会自动进入训练集。OpenAI 条款限制用输出开发竞争模型；本项目是否属于该范围未明确，不能把输出所有权当作训练许可。[官方条款](https://openai.com/policies/terms-of-use/)
- “导出训练集”生成新的版本目录，按独立会话划分训练/验证集，去重原文并固定验证分组；至少两个独立有效会话。500条训练样本、50条独立验证样本只是首轮训练的工程门槛，不是准确率达标的证明。
- “准备训练方案”输出训练配方、当前缺项和可独立运行的训练工具。推荐一个 Hy-MT2 1.8B 基底加 QLoRA；多个老师用于挑选、核对训练样本，不混合不同架构的权重。需额外准备原始 HF safetensors 权重和独立 Python 训练环境，现有 GGUF 用于推理对照。当前不会安装训练依赖、自动下载权重或边运行字幕边训练。
- 训练工具默认只做 `--preflight` 检查，显式 `--train` 才会训练；数据来源、独立验证集和本地权重必须通过检查。RTX4060 Laptop 8GB 的短序列 QLoRA 是否可运行尚未实测；官方标准1.8B LoRA配置要求24GB以上，不能据此保证8GB能训练。[官方训练说明](https://huggingface.co/tencent/Hy-MT2-1.8B/blob/main/train/README.md)

“使用专用模型”始终禁用。即使生成 adapter 或文件写有 approved，也不能激活；未来需要独立的准确率、误译/漏译、人名数字否定和延迟评测，以及明确开放使用后再实现启用。微调主要改善领域表达和术语，不能替代断句、讲话筛选或纠正错误的语音识别。

音频保存上限2GiB，达到上限停止保存新音频并显示状态，保留已有数据；数据写入故障或写入队列满会停止专用模型采集，字幕继续。不会自动删除已有资料。

## 内置 Google / 有道网页翻译

在“更改设置”中的翻译源选择“Google 网页翻译”或“有道网页翻译”，保存后启动。两者均需要联网，无需 API Key 或 Codex 登录；仍需准备本地 SenseVoice、Silero VAD 及已启用的讲话筛选模型。支持日译中和中译日；网页模式使用固定识别语言，不承诺混合语言识别能力。

程序在独立的 WebView2 翻译窗口中输入识别文字、选择语言并读取译文，复用页面处理后续句子，不调用逆向的私有 HTTP 接口。Google 使用[官方文本页面](https://translate.google.com/)，有道使用[官方普通文本页面](https://fanyi.youdao.com/#/TextTranslate)。翻译窗口不会占用或跳转正在采集声音的直播窗口；两种翻译器的浏览器资料分别保存到本地数据目录 `web-translation/google_web` 和 `web-translation/youdao_web`，不复用直播账号 Cookie，不进入程序包。

有道页面通常在后台运行；当前实测 Google 隐藏窗口时不会生成译文，首次翻译会自动显示 Google 窗口，请保持该窗口可见。“打开翻译页面”可显示当前页面；网站需要登录或验证、超时或页面变化时会显示窗口并报告本条失败，由用户处理网站提示。程序不自动登录或破解验证码，不自动切换其他翻译源。暂停 / 关闭会中断所属请求，旧结果不能覆盖新字幕；下次开始重新打开所需翻译页面，保留已保存的资料。

每条请求清除旧原文和结果，确认当前语言对及原文一致后，等待新结果稳定再显示。网页模式没有本地暂译、系统提示词或历史语境控制，严格中文字符校验继续适用；网站保留外文姓名导致不合格时会报告该条失败，不偷偷调用 Codex 修正。Google 是否可连接取决于本机网络；有道同样需要网站服务可用。网页控件可能随网站更新变化，当前实测只能说明测试时可用，不能保证延迟、访问额度或翻译质量。

开发检查工具 `tools/check_web_translation.py` 可用显式独立 profile 连续翻译构造的中日例句并记录耗时；它不采集音频、不写用户设置、不发送直播弹幕。

## Codex CLI 订阅翻译

在“更改设置”选择“Codex CLI（联网，使用 ChatGPT 订阅）”。点击“刷新模型”读取当前账户实际可用列表，从下拉框选择模型和该模型支持的推理强度，然后保存。首次切换到 Codex 且没有列表时自动查询，查询过程不冻结界面、不生成译文；关闭设置会取消所属查询。保存后切换翻译引擎，下次启动沿用模型、推理强度和速度模式。账户默认使用模型目录推荐值；主窗口显示实际生效的模型、推理强度和速度，返回与选择不一致时拒绝开始翻译，不静默降级。

音频采集、讲话筛选、断句、语速复核与识别仍在本机完成；仅把当前识别文字及同通道的少量前文发送到 Codex 翻译。两路方向、开关和翻译源都会记住。按准确性与速度综合考虑，GPT-6.1 Sol 是当前推荐候选；速度对照可选择 GPT-6 Luna，复杂表达质量对照可选择 GPT-6 Astra。官方没有给出中日字幕翻译准确率排名，本机有限固定句对比也不能证明通用冠军。

速度默认“标准”。“Fast”在账户和模型支持时可加速，但会更快消耗订阅额度：官方说明已包含的订阅额度通常按标准的 2.5 倍消耗。程序不会自行购买额度，不默认开启 Fast；界面会明确显示用户选择和实际确认结果。提高推理强度通常更慢，不代表对每一句翻译都有收益。参考：[官方模型定位](https://learn.chatgpt.com/docs/models)、[官方速度与额度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)。

此模式需要本机安装 Codex CLI 并通过 ChatGPT 登录。未登录时，在 PowerShell 执行 `codex login` 后完成浏览器登录，再在字幕软件中重新开始。程序只接受 ChatGPT 订阅登录，拒绝 API Key 登录和其他付费 provider，不提供 API Key 输入，也不会自行购买额度。持续翻译消耗 Codex 订阅额度；联网中断、登录失效或额度用尽会提示，可通过“更改设置”切回本地模型。

Windows 启动时会从现有 Codex 桌面应用、PATH 和 npm 安装中发现原生 CLI，核对版本后使用较新的可用版本，避免双击启动和开发终端命中不同版本。这个过程不安装或升级 CLI，也不修改全局配置。模型列表以实际启动的 CLI 和当前账号返回为准；只有旧 CLI 时，可能看不到新模型，应在“更改设置”刷新并选择列表中的可用模型。

软件通过持久的 `codex app-server` 子进程接入，每路声音短时复用独立的临时会话；同一路按排队顺序翻译，两路互不混用历史。会话最多使用20次翻译请求、120秒或累计12000字节 UTF-8 文本，达到任一预算时重建。文本预算包含系统指令、请求正文与返回正文，不等同于模型的精确 token 数；一个超预算的合法请求仍完整提交，下一次请求重建。暂停、更改翻译源和关闭程序会取消所属 Codex 请求；方向、模型、配置或语音上下文代际变化时也重建，断流、语种切换、未确认识别及补齐字幕隔离旧语境。启用“仅采集当前直播来源”后，内置浏览器导航会清除旧音频和翻译上下文；普通电脑声音模式不根据网页 URL 判断换台。Codex 模式无需本地翻译权重，仍需要识别、VAD 以及启用讲话筛选时的分类模型；切换不会删除本地模型或覆盖本地翻译选择。

开启两路声音时，Codex 为每路固定一个工作线程及 CLI 子进程并行处理；只开一路时使用一个，保持同通道会话顺序。模型、推理强度和速度仍沿用用户设置。只对已经排队、同通道同方向且处于同一上下文代际的最多三句做一次批次请求，不为凑批额外等待；单条与批次可以复用同一会话，每次分别提供严格的 JSON 输出格式。返回按字幕 ID 核对，格式不合格时清除失败会话再逐句重译，联网或额度失败不会扩大重试。第二路启动失败时保留同一模型单路运行并提示，两路仍分别维护会话。尚未开始的同一句旧版本任务会被新版本替换，已开始的旧版结果不能覆盖新字幕。

每次请求仍核对 ChatGPT 订阅登录状态；账号身份变化时停止当前请求并重新验证，身份无法核实时不复用历史。请求失败、超时、取消或格式错误会清除所属 CLI 会话，避免不确定的旧请求继续执行。历史原文只用于理解，旧译文不能覆盖当前原文；短会话不会补回 ASR 漏听的内容，也不保证提升准确率或延迟。

ChatGPT Voice 暂不作为本软件可用的翻译源。本机 CLI 存在实验性语音会话接口，但账户可用性、订阅扣费与连续双路字幕稳定性尚未验证；当前使用文字接入方式。官方资料：[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[ChatGPT 登录与 API 计费区别](https://learn.chatgpt.com/docs/auth)、[ChatGPT Voice](https://learn.chatgpt.com/docs/features/voice)。

下载完成的权重持续保留；切换不会删除其他模型，也不重新下载已有文件。文件未变化时复用校验结果；文件变化或点击“重新校验本地文件”时执行 SHA-256 校验。模型加载仍需要时间，切换不保证瞬时完成。

正常启动不自动下载；首次准备权重需要联网，也可以在其他电脑下载后手动复制。必须保留完整程序文件夹及 `_internal`、`runtime` 目录。模型存放在程序之外，因此更换程序版本可继续使用已下载权重。

## 模型与推荐依据

翻译模型采用官方 GGUF 和固定版本 SHA-256。推荐指数针对本机字幕用途，是有限样本与资源表现的推荐，不能当作准确率或通用模型排行榜。

| 翻译模型 | 下载体积 | 当前定位 |
| --- | --- | --- |
| Hy-MT2 7B Q6_K | 6.16 GB | 当前本机 42 条固定文本质量与速度首选，默认候选 |
| Hy-MT2 1.8B Q6_K | 1.47 GB | 备用；已消除旧模型重复，但口语仍有误判 |
| Qwen3 1.7B Q8_0 | 1.83 GB | 通用模型对照；本批有漏译，不作为默认 |
| Hy-MT2 30B-A3B Q4_K_M | 18.24 GB | 保留手动对照；两轮各 42 条没有一致优于 7B，本机 CPU/GPU 混合且可用内存最低仅 36.6 MiB |

当前识别固定为 **SenseVoiceSmall ONNX INT8 + Silero VAD**，本机设置沿用 **Codex CLI 终稿**。SenseVoice 在 CPU 上使用 4 个线程；讲话筛选和准确优先断句规则保留。本地翻译模型与旧 M2M100 对照模型全部保留，仍支持本地翻译及本地暂译与 Codex 终稿并行。

同一批 28 段日语直播音频的 SenseVoice 识别运算中位数为 0.155 秒；同一段 90 秒音频两轮回放的声音起点到终稿绘制中位数为 10.511 秒、句尾到终稿为 4.333 秒。统计来自开发机器的本地评测，原始录音和报告不随仓库发布；结果包含当时的分句与 Codex 等待，不能把纯识别耗时当作全程延迟。这批素材没有独立听写，尚不能判定真实识别准确率。

翻译推理由本机隐藏的 llama.cpp helper 执行，只监听 `127.0.0.1`，无需用户配置或启动额外服务。支持 CUDA 自动控制显存及 CPU 回退；CUDA 需要兼容的 NVIDIA 驱动。CPU 回退能否跟上连续讲话取决于所选模型，不能承诺所有电脑实时运行所有模型。

## 声音与字幕

### 自动多语识别

“更改设置”默认开启“自动多语识别（日语、中文、英语；译文语言按方向设置）”。旧设置缺少该字段时也默认开启；保存后记住选择。日文→中文通道允许主播偶尔说中文、游戏角色说英语，最终仍输出简体中文；中文→日文通道同样固定输出日语。主窗口实际加载模型旁显示“识别语言：自动多语”或“按通道方向”。如短词、纯日语片段自动模式表现不佳，可关闭该选项对照固定语种。

SenseVoice 自动模式使用 `auto`；关闭自动多语时按通道方向使用 `ja` 或 `zh`。原始识别、异常降速和连续短句音频复核继承同一策略，不将每段按三种语言各跑一遍。检测语种只记录模型原生字段，缺失时保持 `unknown`；汉字不能作为已确定中文的证据。

Codex CLI 的单条、批次以及本地 GGUF 都使用固定目标的混合语言翻译规则，保留已是目标语言的原意、专名、数字与否定，不额外调用一次语言检测。旧 M2M100 需要固定源语言，选择它时明确提示并沿用固定识别，不冒充自动多语支持。

识别和翻译输入/输出继续拦截残余控制标记，拒绝的字幕会释放排队位置，让后续正常内容继续。极短或噪声音频仍可能出现普通文字幻觉，协议清理不能代替真实准确率评测。

中文、日语使用字符密度，英语使用词数判断输出异常，正常英文不会仅因单词拼写长而触发 CJK 密度阈值。明确的连续英语保留有限前文，语言切换或不确定混语边界隔离参考；英语不套用中日句尾拼句规则，游戏单词不独自证明语言已切换。自动模式仍可能误识别短句、同一句多语及专名，不能分离重叠人声。单测验证路由，不代表真实直播准确率提升。

长讲话默认以约5.5秒为软目标，在Silero确认约0.45秒自然停顿时独立分段翻译；前后可使用有界原文背景，不把这些长段重新拼成整句。没有自然停顿仍使用10秒硬限；硬切后的连续短尾最多等待约1.8秒合并（512样本窗口取整最多约1.824秒），不丢弃真实短答。软目标不是固定每5.5秒截断，也不能保证语义完整或识别正确。

- 麦克风使用默认输入设备；电脑声音使用默认播放设备的 WASAPI loopback，无需虚拟声卡。默认设备变化后自动重连。
- 默认按准确率优先处理：静音分句等待约 1.1 秒，保留句首 0.3 秒。疑似半句目标额外等候 1.2 秒，ASR 忙时到本轮识别返回再处理；相邻续句最多合并一次，连续且总长不超过 4 秒时重新识别整句，否则按原文组合翻译。明确的半句句号会在组合时移除，避免人为句界破坏否定、条件和引述关系；不添加词或改写事实，诊断记录保留原始两段。问句、感叹句、引用边界和完整短回复保守处理。每路保留最近五条字幕和待完成片段，支持暂停、置顶、字号与透明度。
- 支持的翻译模型参考同一路最近三段原文（按音频采集时间 20 秒有效、最多 384 字符，本地 tokenizer 可用时另限制为 256 tokens），优先保留完整的最近片段，超预算时舍弃整段旧前文；只有最新单段本身超预算才截断参考。只翻当前文字，不翻旧背景；待核对原文不加入后句背景，断流、识别失败、暂停或设置切换时重置参考。补齐字幕原地更新，旧版本结果不能覆盖新原文。历史扩展不补回尚未说出的句尾，也不能分离同一通道的不同说话人。
- 正常识别只运行一次。空结果、乱码、重复或异常文字密度时，使用保持音高的 WSOLA 0.92 倍速复核；分歧保留原文并标记待核对，复核非空不代表准确。生成上限异常会尝试有界分段恢复，失败不会输出残缺拼接。普通片段不全局减速；异常复核可能额外耗时超过 1–2 秒。
- 开启讲话筛选时，CPU 上运行 Zipformer Small INT8 声音分类模型（约 27 MB），在 ASR 前检查讲话、音乐和歌唱分数。高置信度的纯音乐/唱歌片段跳过；包含讲话的背景音乐片段、短句和不确定片段优先保留。分类模型缺失或损坏会提示，不会静默假装筛选已启用。
- 这属于片段筛选，不能从同时重叠的主播讲话和歌曲人声中彻底分离出讲话。短于 1.5 秒的片段保守保留；漏筛与误判仍可能存在。新版可在筛选后使用 GTCRN 语音增强或 UVR 伴奏分离；处理不等于识别准确率提升，可切回原音对照。
- 识别与翻译分别排队，翻译变慢不会阻塞识别。文本队列在内存保留最多 64 个任务，超出部分暂存到程序自建的临时 SQLite 文件；顺序、公平调度及原文保留，排队时显示数量和最早等待时间。正常处理完或停止会清理程序自己的临时缓存，不影响模型和设置；此缓存不用于崩溃后恢复。持续输入超过翻译吞吐仍可能积压，不承诺无延迟。识别音频队列仍有 30 秒上限，识别本身过载或磁盘缓存失败会明确提示并暂停采集。
- 连续检测为语音约 10 秒后主动切段，包含检测启动时间，非严格从音频起点 10 秒；讲话中途切段可能影响句子语境。疑似半句以音频采样位置核对续句；已排队的连续音频可延长候选保留，最多额外 30 秒、合并音频跨度不超过 22 秒，避免处理延迟把否定续句错误拆开，也防止无限等待。已修复极长片段因历史缓冲区裁剪而丢句首的问题。
- 建议耳机避免两路重复收声。字幕准确性还受噪声、断句、人名、语境和 ASR 影响。

### 日语主播直播翻译

Codex 与本地 GGUF 在日语或混合语言译为中文时，共享 `japanese_livestream_v1` 提示规则：自然简体中文口语、保留否定与改口、保留有意义的犹豫和语气、不补写缺失句尾、不猜姓名对应的性别或身份，也不把引用和玩笑改成说话人本人的事实。所有中文目标（包括英语译中文）要求完整中文译文，人名、昵称和游戏名使用通行中文名，否则音译为中文，不能保留外文原名或直接删除姓名。

本地暂译、Codex 终稿及弹幕提交前均检查字符：允许汉字、数字、空格与正常标点，拒绝日文假名、英文字母及其他外文字母。Codex 和本地 GGUF 返回外文时最多重新翻译一次，仍不合格则不显示该译文、不推送，后续字幕继续处理；语言不符不会重启健康的常驻推理进程。汉字在中日间共享，字符校验不能判断纯汉字词的语义，语义仍由模型翻译。原文栏保留识别结果，中译日功能不受中文输出检查影响。

根据当前原文选择最多三条相关术语提示，例如 `ナイス`、`ワンチャン`、`スパチャ`、`エイム`；术语按上下文解释，不在 ASR 原文上做机械替换，不把旧背景或原话中的指令拼进系统指令。Codex 将变化的术语提示放入每次请求的 `term_hints`，稳定的系统指令不会因为出现不同术语而反复重建。Codex 保留单条及批次 JSON/ID 输出契约；本地 GGUF 保留 `temperature=0`，新增提示同样受输入预算限制，先裁旧背景而不截断当前待译文字。翻译风格规则与文字回归测试不等于真实直播准确率保证。

### 本地暂译与 Codex 终稿并行

在“更改设置”的翻译源中选择“混合翻译：本地暂译 + Codex 终稿”。本地模型沿用“模型管理”里保存的翻译选择；Codex 的模型、推理强度和速度在同一设置窗口中选择。需要已准备好的本地翻译权重和已通过 ChatGPT 登录的 Codex CLI，权重仍独立于程序包。

每段识别文字同时进入本地和 Codex 的独立队列，两者各自根据同一份原文和有界前文翻译。较快的本地结果标为“本地暂译”，Codex 完成后在原字幕行更新为“Codex 终稿”。Codex 直接翻译原文，不根据本地暂译纠错；若 Codex 先完成，迟到的本地结果只保留为候选，不覆盖终稿。原文补齐、修订、上下文代际或运行会话变化时，旧任务结果不能覆盖新字幕。

本地使用一个驻留的翻译引擎，公平处理两路声音；Codex 保持每路有序的独立工作线程与短会话复用。两份队列各自暂存超出内存预算的任务，不为凑批等待。每段都会请求 Codex 终稿，不按未经校准的“置信度”跳过；并行模式不会减少订阅调用次数。

Codex 不可用或请求失败时，已有的本地文字保留为“暂译 · Codex 未确认”；本地失败时仍等待 Codex。两路均失败才显示整体失败。普通暂停时保留没有在推理的已加载本地引擎，正在执行的所属本地请求会被中断，恢复后按需重建 helper；关闭程序释放两路所属进程。该模式可提前看到译文，但终稿仍取决于 Codex 响应，本地推理也会占用 CPU、内存或显存，不能保证总延迟或准确率提升。

诊断分别记录暂译与终稿的模型、耗时和状态；专用模型积累保存独立的本地与 Codex 候选，沿用已有的数据审核与训练授权要求，不会在使用过程中自动微调。字幕“暂译／终稿”状态与语音断句的“未完成原文／确认原文”分别管理。

## 本地数据

Codex 与混合模式会将识别文字和少量前文发送到云端，遵循 ChatGPT 账户或工作区的数据政策；音频本身不发送给 Codex。Google / 有道网页模式将当前识别文字输入对应网站，适用对应网站的数据政策；网页本身可能把输入保存在翻译浏览器历史中，程序不记录带原文的页面 URL 或账号凭证。

设置：`%LOCALAPPDATA%/FanyiJi/settings.json`。

模型：`%LOCALAPPDATA%/FanyiJi/models`。翻译选择写入该目录的 `translation/backend.json`，识别选择写入 `asr/backend.json`。下载中的 `.part` 文件保留，可续传；完整性校验通过才启用。

上述路径表示新安装默认位置；复用旧数据目录时，以实际目录为准。

专用模型积累开启时，普通运行会在上述独立目录保存实际音频片段、识别原文和候选译文。可在“专用模型”关闭并保留该开关；关闭且未开启诊断采样时，普通运行不保存新录音或字幕文本。日志只记录状态、耗时和错误类型。明确使用 `--diagnostics-output <新目录>` 时，另存实际程序处理的完整音频片段、识别原文和译文供采样评测；不会启动第二套模型或上传音频，暂停即停止新采样。筛选记录保留原始 WAV；被屏蔽的片段另存处理后 WAV，独立模型对照使用实际送入 ASR 的音频。关闭程序或更改音频/模型设置会结束该次诊断采样。未结束的句尾不冒充终稿。

主窗口显示最近终稿的“全程”和“句尾等待”，暂译单独计时。全程从本段首个采集音频样本（包含可用的前置缓冲）计到字幕标签在可见窗口完成 Qt 绘制；句尾等待从最后音频样本计到同一绘制时刻。悬停可查看识别开始到终稿、分段、识别、翻译排队、请求和界面阶段。原文尚待确认时的 Codex 结果不计为已确认终稿；确认等待独立归因。隐藏、未进入可见区域、失败或已被新版本替代的字幕不冒充已经看到，实际显示器扫描与物理设备延迟不在此测量范围内。

`LATENCY` 日志只记录模型标识和计时。诊断采样的 `performance_summary` 提供最近200条实际绘制记录的 P50/P95，并分别保留暂译与终稿。旧 `MT end_to_end` 和事件 `latency` 仍保留原兼容口径：最后音频样本到后台发布，不能替代真实绘制计时。拼句音频与早期识别可以重叠，阶段累计工作耗时不能简单相加等同于全程。

耗时记录分别统计讲话筛选、ASR 运算、ASR 排队、翻译排队和 Codex 认证/建会话/启动/接收/清理；`first_output_seconds` 表示接收阶段等到首个输出事件的时间，`output_completion_seconds` 表示随后到完整输出的时间，二者属于 `receive_seconds`，不能重复加总。接收阶段包含网络、服务调度和模型生成，CLI 不提供足够数据把它们分别计时。`thread_reused`、`thread_turn`、`thread_history_bytes`、`thread_reset` 记录会话复用及预算。批次请求按唯一 ID 计数，不能把三句共享的请求耗时累加成三次调用。

正常直播停顿的语境保留按已有20秒原文有效期判断，采集代际、方向、语言或识别不确定性变化仍隔离语境；半句拼接的1.8秒连续性限制保持独立，避免普通停顿导致每句重建 Codex 会话。当前保持准确优先的识别模型，性能选型需用相同录音对照，不能仅凭线程数或模型大小认定更快。

半句候选在捕获音频已证明拼接窗口关闭、没有仍在讲话或保留的片段、没有已排队续句时提前确认；默认保守检测余量约0.672秒，按捕获采样水位判断，不额外固定睡眠。无法证明时继续保留原15秒候选及已有排队保护。已返回但原文尚未确认的 Codex 结果显示“等待后半句确认”，确认后才标记终稿。

## 开发与打包

Python 3.12，依赖沿用 `pyproject.toml` 固定版本。入口 `run.py`，测试 `python -m pytest -q`，原生运行库准备 `tools/prepare_llama_runtime.py`，打包 `tools/build.py`。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe run.py
```

安装依赖需要联网；首次运行通过模型管理下载必要模型。本地 GGUF 翻译还需按 `tools/prepare_llama_runtime.py` 准备原生运行库；Codex 模式需要另行安装并登录 Codex CLI。源码仓库不提供任何已登录账号或默认凭据。

本机更新使用 `tools/build.py --install-local`，先在固定 `build/portable` 生成程序包，再更新根目录的 `翻译姬`（首次改名时安全迁移旧安装目录）；更新前须关闭该目录中的字幕程序。安装完成后核对全部文件 SHA256 并运行 `--smoke-test`，两项成功才自动清理已验证的旧安装备份，以及与当前或已验证旧安装完全一致的 `build/portable/翻译姬`、`dist/翻译姬` 程序包，只保留根目录最新版；失败则保留备份和包，未知或被更改的目录也保留并报告。普通打包使用 `tools/build.py`，输出到固定 `dist/翻译姬`，不触发本机版本清理。单独使用 `tools/install_local.py --source <程序包>` 仍保留备份，不自动清理。清理范围不包含模型、浏览器登录资料、设置、日志和源码。安装器校验旧管理清单并备份，更新后移除已退出清单的旧程序文件，拒绝覆盖未知文件或用户资料。仅独立训练工具的两种已验证 Python 导入缓存可以保留，单独记录缓存校验值，确保旧缓存不能遮蔽更新后的源码；不会把缓存当作新版程序文件打包。

打包只包含程序、运行库及许可，构建检查禁止 `.gguf`、`.onnx`、`.safetensors`、`.pt`、`.pth` 和 `model.bin`。程序配置与模型存储在外部目录，不随程序更新覆盖。

`--smoke-test --screenshot <PNG>` 仅验证界面，不采集声音或写用户设置。`--self-test --self-test-output <JSON>` 用本地官方样本验证真实模型加载和非空输出，样本放在模型目录 `self_test` 中；不采集设备声音，不代表准确率验收。

开发机器的实际对比报告和录音单独保留，不随源码仓库发布。不把模型分歧、消除重复或合成单元测试当作识别/翻译准确率。
# 内置直播浏览器

主窗口点击“直播浏览器”，首次在专用窗口扫码登录哔哩哔哩，输入直播间号或 `https://live.bilibili.com/<房间号>`，点击“打开直播间”。这是翻译姬自带的最小网页窗口，不需要安装字幕弹幕桥扩展。登录状态存放在外部用户数据目录 `browser/default`，不读取或复制原 Chrome 账号资料，不进入程序包。程序退出时关闭浏览器辅助进程；再次打开沿用同一份会话。

浏览器使用 **Microsoft WebView2 Evergreen**。第一次打开浏览器管理窗口自动联网检查官方 WebView2 稳定版目录，后续每小时检查，可关闭自动检查或手动“检查更新”。显示正在运行、本机安装和微软公开目录三个版本；无法联网时显示未确认。Evergreen 更新由 Microsoft Edge Update 安装，不随翻译姬打包；已安装新内核后需关闭并重新打开浏览器，刷新网页不会切换内核。目录新版本不保证立即进入当前设备的更新批次。缺少 Runtime 时可通过“微软官方内核下载”安装 Evergreen。

浏览器是独立辅助进程，不占用 Qt 字幕窗口主循环。重启程序不自动打开直播间。沿用已保存的登录会话和设置，由用户在管理窗口点击“打开直播间”或“打开验证直播间”；始终只保留一个内置浏览器窗口。

## 音源与语音处理

点击主窗口或“更改设置”中的“音源与语音处理”。可选“仅采集当前直播来源”，然后在内置浏览器打开并播放目标直播间或 B站普通视频。程序读取原生 `CoreWebView2.BrowserProcessId`，使用 Windows process loopback 捕获该 WebView2 浏览器及其子进程的音频，排除独立 Chrome、播放器和其他应用；Windows 需支持 build 20348 或更新版本的进程音频捕获。不支持或采集失败时显示错误，不会退回全电脑声音采集。麦克风通道仍按原设置工作。关闭此开关可恢复原来的默认播放设备采集。

语音处理有三个选项，保存后后续启动沿用：

- **GTCRN 语音增强（默认）**：抑制背景噪声，适合先进行本机 CPU 对照。模型约 0.51 MiB，固定哈希校验，原始音频按固定比例保留以减少过度处理。增强对伴奏、歌声和游戏角色对白的效果取决于音频，不能承诺识别一定更准。
- **UVR 伴奏分离**：提取人声、减弱伴奏，模型约 28.3 MiB。CPU 处理比 GTCRN 慢，短句也有分块开销。人声包含主播、唱歌和游戏角色，不具备锁定主播身份的能力。
- **关闭（原音）**：不做增强或分离，保留 Silero VAD、讲话筛选和 SenseVoice 识别，适合清晰讲话或处理后识别变差的来源。

处理链为选定音源 → Silero VAD 断句 → 原音讲话筛选 → 语音增强／伴奏分离 → SenseVoice → 当前翻译模型。处理在识别工作线程执行，不堵塞音频采集；保留原始采样时钟、时长和断句策略。缺少模型、模型损坏、处理异常或输出无效时回退原音，主界面显示回退状态，日志记录原因和处理耗时，不再因声纹不匹配丢弃讲话。

普通视频支持 `https://www.bilibili.com/video/BV…` 或 `/video/av…`，分享链接的查询参数不作为音源身份保存。普通视频可以生成字幕，其实际直播间号为空，不伪造直播间或向直播间推送这些视频字幕。导航、关闭浏览器或音源断流会使旧音频任务失效，防止上一页面的字幕混入新页面。

首次使用在该窗口下载处理模型，也可以选择关闭处理；模型保存于外部用户模型目录 `models/audio_processing`，不进入程序包。音源开关存入 `live-source-settings.json`。旧版音源开关可迁移，旧声纹档案不再读取或用于筛选；账号登录、词级过滤规则和已下载翻译模型继续保留。

指定音源只能排除其他应用声音；单个直播音轨中已经混合的主播和游戏对白仍可能一同识别。当前不要求录制主播声音，也没有声纹登记或相似度门槛。

## 本机译文弹幕推送

“更改设置 → 直播弹幕设置”或主窗口“直播浏览器”打开同一个管理窗口。登录账号，填写直播间，勾选“同步终稿译文到直播弹幕”，选择来源并保存。默认来源是电脑声音，默认发送间隔为 3.5 秒，不能设置更低。无需 Chrome 扩展、导出 Cookie 或填写 CSRF。页面在已登录的内置 WebView2 中执行固定发送请求，账号凭证留在浏览器中。

- 仅发送已确认的终稿；本地暂译、识别待核对、失败和旧版本不进入队列。弹幕正文每个标点替换为一个空格，保留已有内部空格的顺序，用 `【】` 包裹；每段连同括号及空格不超过 40 个加权单位，且不超过当前账号网页允许值。标点清理只用于弹幕，不改写字幕终稿和模型训练数据。网页可打印 ASCII 计 1，其余每个 UTF-16 单位计 2；汉字通常计 2，`【`、`】` 各计 2。读取不到账号上限时采用网页的保守默认加权值 20，发送前再次检查，不把超限正文提交出去。
- 正文至少 2 个有效字符的每句译文独立按 FIFO 顺序发送；汉字、数字各计 1，空格及外层【】不计入短片段阈值。正文不足 2 个字符时保留在原位置，仅与紧接的下一句合并；2 字短句不跨句拼凑，不为了凑长度添加内容。
- 长句达到加权上限直接切分，余文进入下一段；不搬前段的字均衡尾段，也不拼接后续独立句。最后不足 2 个有效字符的尾段才保留并等待下一句。账号上限不足以容纳有效正文时保留待发，不提交超限消息。未确认的已提交正文仅作只读核验，不回头改写。旧版合并记录保持兼容读取。
- 发送请求串行；上一条 POST 返回后至少等 3.5 秒再发下一条，因此相邻请求起点间隔包含网络耗时，实际可能略长。只读登录检查和页面核验不额外等待 3.5 秒。
- FIFO 队列保存在用户数据目录的 `danmaku-queue.sqlite3`，本轮运行与暂停期间不过期。每次新进程启动清空上一轮待发、判重窗口和推送统计，并保留一份最近重启前的数据库备份；保留过滤规则与失败记录，不恢复旧待发内容。同房间相同规范译文仅在上次入队或单字合并后的 10 秒内跳过，超过 10 秒允许再次入队；跳过不会延长窗口。同一字幕版本的重复回调始终拦截。旧房间队列不会转发到新房间。
- 分别显示“接口回执”和“页面收到”。`HTTP 200/code 0` 不直接算投递成功：发送前记录聊天列表中精确同文的数量，提交后进行 15 秒快速只读核验，仍无法确认时改为按配置间隔持续只读检查，数量增加才记页面收到。旧同文仍显示不能算本次成功；缺少发送前基线或列表滚动裁剪导致无法确认时保留待核验。这仍不能独立证明所有其他观众收到或刷新后留存。
- 发送失败（包括 f、明确拒绝、未提交错误和结果未知）成功保存待分析记录后，移出主发送队列，不重投该失败正文，后续片段及消息按原顺序继续。失败正文保存在独立处理记录，交给 Codex 修正与专用测试验证；它不计为发送成功。若失败记录无法保存，则保留队首避免丢失。
- 已接受但尚未看到页面回显的消息先作只读核验，15秒仍未确认则保存独立处理记录并让后续队列继续。结果未知不重新提交同一正文；专用测试验证未知也只读检查，不重复POST。未登录或页面连接异常会等待正常登录与连接，不复制凭证或改变 IP。
- “清空待发队列”先显示可清理数量和需保留数量，确认后取消尚未提交的消息；发送中、已提交但结果未知的当前片段保留供核验，不自动重发。清理不关闭推送，新终稿继续入队。
- 操作记录为队列同目录 `delivery.jsonl`，使用 UTC+8 时间；不记录账号凭证、译文正文或接口原始响应。

### 自动失败处理与专用测试房间

每次启动清空上一轮队列及统计，保留未完成的失败记录、已保存规则和浏览器登录资料。失败译文修正有独立的“开启失败译文修正／停止失败译文修正”按钮，旧配置默认关闭，不影响普通字幕和正式发送队列。开启前先保存不同于正式房间的“AI验证直播间”；点击开启时自动打开测试页，普通程序启动不自动打开直播间。

Codex 使用独立、无工具的请求，只返回修正后的中文正文。本地先选择词库命中的词、短句段或局部字词片段，每轮只允许改当前片段中的一个局部词，保留完整句子用于测试；数字、否定和姓名仍受保护。一次测试明确拒绝后继续新的局部修正，不再有每句最多三次的限制；已试方案持久保存并提供给后续分析，同一旧方案不会再次提交。AI返回原句、重复方案或无效修改时等待5秒继续下一轮；CLI暂不可用时逐步延长等待，最多120秒，开启状态下仍会继续重试。外文姓名先完整转为中文，随后才进行逐词修正；已有中文不能因此被改写或删除。

修改后的正文仅保存在失败记录中，不提前创建过滤规则。测试房间应为自己管理或获准测试的房间；未配置正式房间时保持正式推送关闭。测试请求串行且间隔不少于 3.5 秒，须正常接受回执与之后新增的精确同文页面计数同时成立，才标记处理完成，再对比原句与修正句保存 2–12 字符的全局局部词规则。规则保留验证来源，人工规则不被覆盖。停止按钮取消所属AI任务并停止新测试，已提交请求的回执保留供后续核验。

返回 f 或明确拒绝不会创建规则；结果未知持续只读核验、不重投未知请求。主发送失败句成功保存独立记录后直接跳过该条，后续消息继续，规则管理的 AI 和验证不依赖原队首。失败库写入异常时保留原条并自动重试保存；若此时重启，明确待移交的失败正文先进入独立持久记录，再清空运行队列和统计，恢复写入后自动交给 Codex，不恢复旧发送队列。连续重启也不会清除这些交接记录。测试成功仅代表该次测试房间的页面观察，不证明全站禁词、正式房间必定可发或所有观众收到。规则支持查看、编辑和停用。

### 本地过滤词与中性替换

在直播浏览器管理窗口打开“过滤词管理”，登记原词并选择“中性替换”或“从弹幕删除”。所有已保存规则统一应用到全部直播间，新增人工规则及验证成功生成的规则也一样；界面不再提供规则的房间范围选项。旧版按房间保存的规则自动兼容为全局规则，保留验证证据；同词冲突按确定顺序选取，原记录保留在迁移归档中。失败来源和验证房间只是记录与证据，不限制规则作用范围。没有合适表达时可使用“已过滤”；需要删除时必须选择删除动作，旧版空替换仍使用“已过滤”。后续弹幕在本地处理，再去标点、按有效字符判断短片段，并按含【】加权 40 单位及账号限制顺序拆分本句；满 2 字的句子独立发送，单字片段只与紧接的下一句合并。字幕终稿和训练样本保留原文，不为每条弹幕追加 Codex 请求。规则从长词到短词匹配，替换结果不再次级联匹配。

发送失败会把实际失败正文保存在本机待分析记录中，包含房间、原因、次数和时间；重复失败累计次数，不自动把句中的字或词认定为禁词。确认具体原词及处理方式并保存后，规则应用到后续新译文和尚未开始提交的完整译文。明确返回 `f` 的队首在下一次只读检查中若未观察到回显次数新增，会应用新增或修改的已确认规则，仅修正当前包及尚未发送的续包，保留 FIFO 顺序和发送间隔。已经有新回显则直接推进；发送中、已接受但待核验、结果未知的消息不改写。删除后正文为空或续包损坏时保留消息并提示。页面计数只是当前观察，不能保证没有延迟广播；修正后的新请求仍需单独核验。

规则和候选位于外部用户数据目录的 `danmaku-content-filter.json`，不包含在程序包中。启用 AI 失败处理时，失败正文和白名单内的回执事实会发送给已登录的 Codex CLI；不发送 Cookie、CSRF、账号身份和原始请求头，运行投递日志仍不记录正文。词库读取或保存失败会提示，不能把未成功保存的规则当成已生效。平台 `f` 或发送失败不提供可靠的具体禁词证据；本次没有找到官方公开的完整普通弹幕禁词表。B站官方[醒目留言说明](https://live.bilibili.com/blackboard/live-superchat-intro-web.html)要求聊天内容符合社区规则并说明会审核敏感内容，但该说明不能用来确定普通弹幕 `f` 的原因。

“参考词库与检测”页可查看本地参考词、类别、来源版本和许可证，搜索词条并保存检测白名单。失败句会自动离线检测，结果保存在候选记录中，显示命中的词及原文位置；同一句反复失败时沿用检测缓存，词库或已确认规则变化后才重新检测。未命中会明确显示“发送失败原因仍未确定”，不会推断正常词是禁词。词库损坏只影响检测提示，不停止字幕或发送队列。

参考词条可以设置 `room` 限定检测房间；省略或留空表示通用参考。通过同一账号同一房间的人工对照确认的触发词可标注为 `user-confirmed-trigger`，单独保存实测来源，不能推导为全站永久禁词。它仍是检测提示，和已保存的中性替换规则分开管理。

外部参考词库单独存放在用户数据目录的 `danmaku-wordlist.json`，不进入分发包，也不调用 Codex 或联网检测。可运行 `.venv/Scripts/python.exe tools/prepare_danmaku_wordlist.py` 下载固定版本的 [Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon) 六个小分类词表，保留 MIT 许可证与来源、排除单汉字并去重，得到 1,426 个参考词。该命令遇到已有词库会退出，保留用户词库和白名单。来源包含广告、暴恐、涉枪涉爆、色情及其他分类，普通游戏词也可能命中，因此只作参考提示，用户确认的中性替换规则才改变后续弹幕。

开源参考：[GitHub B站直播社区屏蔽词研究](https://github.com/FHChen0420/bili_live_shield_words)最贴近同传场景，但未声明许可证，不复制其代码或词表；[Gitee wordfilter](https://gitee.com/humingzhang/wordfilter)提供通用 DFA 和黑白名单设计，仓库黑名单只有演示词，不能作为完整 B站词库；[Gitee badwords](https://gitee.com/maslonge/badwords)为较旧通用名单，未作为默认数据源。

该功能只由 `tools/build.py --install-local` 给当前机器授予本地启用标记；标记和队列存放在外部用户数据目录，不进入程序包。普通分发版不开放推送，推送默认关闭。此限制用于本机功能分发隔离，不等同于不可破解的授权系统。
